1.  PRÉSENTATION GÉNÉRALE DU PROJET
══════════════════════════════════════════════════════════════════════

Le dossier client_web/ contient une interface web PUBLIQUE (sans
authentification) qui permet aux utilisateurs de poser des questions
en langage naturel sur les produits et les stocks.

C'est une application 100% statique : HTML + CSS + JavaScript.
Pas de serveur, pas de base de données, pas de Python.

Elle communique avec un service externe appelé "AI Query Service"
via une simple requête HTTP POST.

Architecture en 3 couches :
┌─────────────────────────────────────────────────────────────┐
│  client_web/ (HTML/CSS/JS)  ← Interface utilisateur        │
│     ↓ POST /questions                                       │
│  AI Query Service (pas encore créé)  ← Traitement du langage│
│     ↓ requêtes API                                          │
│  backoffice/ (Flask + PostgreSQL)  ← Données                │
└─────────────────────────────────────────────────────────────┘

3.  index.html — LA PAGE PRINCIPALE (HTML)
══════════════════════════════════════════════════════════════════════

Le HTML (HyperText Markup Language) est le langage qui structure
le contenu d'une page web. C'est comme le squelette d'un corps
humain : il définit où vont les éléments.

══════════════════════════════════════════════════════════════════
3.1  Structure de base d'un document HTML
══════════════════════════════════════════════════════════════════

<!DOCTYPE html>           ← Indique au navigateur que c'est du HTML5
<html lang="fr">          ← Racine du document, langue = français
<head>                    ← En-tête (métadonnées, pas affiché)
  <meta charset="UTF-8">  ← Encodage des caractères (accents, etc.)
  <meta name="viewport">  ← Responsive design (adaptation mobile)
  <title>...</title>      ← Titre affiché dans l'onglet
  <link rel="stylesheet"> ← Lien vers le fichier CSS
</head>
<body>                    ← Corps visible de la page
  ... contenu ...
  <script src="...">      ← Lien vers les fichiers JavaScript
</body>
</html>

══════════════════════════════════════════════════════════════════
3.2  Éléments HTML utilisés dans index.html
══════════════════════════════════════════════════════════════════

<header>        → En-tête de la page (logo + titre + sous-titre)
<section>       → Section thématique (regroupe du contenu)
<div>           → Division générique (boîte sans signification)
<form>          → Formulaire (pour envoyer des données)
<label>         → Étiquette d'un champ de formulaire (accessibilité)
<textarea>      → Zone de texte multi-lignes (pour la question)
<button>        → Bouton cliquable
<span>          → Texte inline (sans retour à la ligne)
<img>           → Image
<ul> / <li>     → Liste non ordonnée (à puces)
<h1>, <h2>      → Titres (niveau 1, niveau 2)
<p>             → Paragraphe

══════════════════════════════════════════════════════════════════
3.3  Attributs HTML importants
══════════════════════════════════════════════════════════════════

id="question-form"    → Identifiant unique (utilisé par JS/CSS)
class="page__header"  → Classe CSS (pour le style, peut être partagée)
hidden                → Cache l'élément (display: none)
disabled              → Désactive le champ/bouton
required              → Champ obligatoire
maxlength="1000"      → Limite de caractères
placeholder="..."     → Texte indicatif dans le champ
novalidate            → Désactive la validation HTML native
aria-live="polite"    → Accessibilité : annonce les changements
aria-hidden="true"    → Accessibilité : cache des lecteurs d'écran
onerror="..."         → Événement JS en cas d'erreur (ex: image absente)

══════════════════════════════════════════════════════════════════
3.4  Ordre des scripts JavaScript
══════════════════════════════════════════════════════════════════

Les scripts sont chargés DANS L'ORDRE à la fin du <body> :

1. js/config.js    → Définit window.APP_CONFIG (URL de l'API)
2. js/utils.js     → Définit l'objet Utils (fonctions utilitaires)
3. js/api.js       → Définit l'objet Api (communication HTTP)
4. js/ui.js        → Définit l'objet Ui (manipulation du DOM)
5. js/events.js    → Définit l'objet Events (écouteurs)
6. js/app.js       → Initialise tout au chargement de la page

Pourquoi cet ordre ? Parce que chaque fichier dépend du précédent :
- api.js utilise config.js (l'URL)
- ui.js utilise utils.js (escapeHtml)
- events.js utilise api.js et ui.js
- app.js utilise ui.js et events.js

4.  LES FICHIERS CSS
══════════════════════════════════════════════════════════════════════

CSS (Cascading Style Sheets) = langage qui décrit l'apparence
visuelle des éléments HTML. C'est comme les vêtements et le
maquillage du squelette HTML.

══════════════════════════════════════════════════════════════════
4.1  style.css — Point d'entrée
══════════════════════════════════════════════════════════════════

@import url("reset.css");       ← Importe reset.css
@import url("variables.css");   ← Importe variables.css
@import url("layout.css");      ← Importe layout.css
@import url("components.css");  ← Importe components.css

@import = directive CSS qui inclut un autre fichier CSS.
L'ordre est important : reset d'abord, puis variables, puis le reste.

══════════════════════════════════════════════════════════════════
4.2  reset.css — Normalisation
══════════════════════════════════════════════════════════════════

Chaque navigateur (Chrome, Firefox, Safari) a ses propres styles
par défaut. Le reset.css les annule pour partir d'une base
identique partout.

Concepts clés :

* { box-sizing: border-box; }
  → Tous les éléments (*) incluent les bordures dans leur largeur.
  → Sans ça, si tu mets width:100% + border, ça dépasse.

body { min-height: 100vh; }
  → Le corps fait au moins 100% de la hauteur de l'écran.
  → vh = viewport height (hauteur de la fenêtre).

img { max-width: 100%; display: block; }
  → Les images ne dépassent jamais de leur conteneur.
  → display: block évite l'espace blanc sous l'image.

button { cursor: pointer; border: none; background: none; }
  → Les boutons ont une main au survol, pas de bordure, pas de fond.

a { color: inherit; text-decoration: none; }
  → Les liens prennent la couleur du texte parent, pas de souligné.

ul, ol { list-style: none; }
  → Les listes n'ont pas de puces par défaut.

overflow-wrap: break-word;
  → Les mots trop longs passent à la ligne (évite les débordements).

══════════════════════════════════════════════════════════════════
4.3  variables.css — Les variables CSS
══════════════════════════════════════════════════════════════════

:root { ... } = pseudo-classe qui représente la racine du document
(<html>). On y déclare des variables CSS accessibles partout.

Syntaxe d'une variable CSS :
  --nom-de-la-variable: valeur;

Utilisation :
  color: var(--nom-de-la-variable);

Avantages des variables CSS :
  1. Centralisation : changer une couleur à un seul endroit
  2. Cohérence : pas de fautes de frappe
  3. Maintenance : facile à modifier

Les catégories de variables :

Couleurs :
  --color-primary: #0f3460;        → Bleu foncé (couleur principale)
  --color-primary-light: #1a4f8a;  → Bleu plus clair (hover)
  --color-success: #1b7a3d;        → Vert (succès)
  --color-error: #8a1c1c;          → Rouge (erreur)
  --color-warning: #8a5a00;        → Jaune/orange (avertissement)
  --color-bg: #f4f6f9;             → Fond de la page (gris clair)
  --color-card-bg: #ffffff;        → Fond des cartes (blanc)
  --color-text: #23272f;           → Texte principal (presque noir)
  --color-text-muted: #6b7280;     → Texte secondaire (gris)
  --color-border: #dfe3e8;         → Bordures (gris clair)

Espacements :
  --space-xs: 0.25rem;   → Très petit (4px)
  --space-sm: 0.5rem;    → Petit (8px)
  --space-md: 1rem;      → Moyen (16px) = taille de police de base
  --space-lg: 1.5rem;    → Grand (24px)
  --space-xl: 2rem;      → Très grand (32px)
  --space-2xl: 4rem;     → Énorme (64px)

  L'unité rem = relative à la taille de police de l'élément racine.
  1rem = 16px par défaut. Avantage : si l'utilisateur change la
  taille de police, tout s'adapte.

Bordures :
  --radius-sm: 4px;      → Coins peu arrondis
  --radius-md: 8px;      → Coins arrondis
  --radius-lg: 12px;     → Coins très arrondis

Ombres :
  --shadow-sm: 0 1px 2px rgba(0,0,0,0.05);   → Ombre légère
  --shadow-md: 0 4px 6px rgba(0,0,0,0.07);   → Ombre moyenne

  rgba(0,0,0,0.05) = noir à 5% d'opacité.

Polices :
  --font-family: "Segoe UI", Tahoma, ...;  → Police (avec fallbacks)
  --font-size-sm: 0.85rem;   → Petit texte
  --font-size-md: 1rem;      → Texte normal
  --font-size-lg: 1.25rem;   → Grand texte
  --font-size-xl: 1.5rem;    → Très grand texte

Transitions :
  --transition-fast: 150ms ease;   → Animation rapide
  --transition-normal: 250ms ease; → Animation normale

5.  LES FICHIERS JAVASCRIPT
══════════════════════════════════════════════════════════════════════

JavaScript (JS) est le langage de programmation qui rend la page
interactive. C'est comme les muscles qui font bouger le squelette.

Chaque fichier JS utilise le pattern "IIFE" (Immediately Invoked
Function Expression) :

const MonModule = (() => {
  // Code privé (pas accessible de l'extérieur)
  function fonctionPrivee() { ... }

  return {
    // Code public (accessible via MonModule.fonctionPublique)
    fonctionPublique: fonctionPrivee,
  };
})();

Avantages :
- Pas de pollution de l'espace global (window)
- Code organisé en modules
- Parties privées et publiques

══════════════════════════════════════════════════════════════════
5.1  config.js — Configuration
══════════════════════════════════════════════════════════════════

window.APP_CONFIG = {
  AI_QUERY_URL: "http://localhost:8000/questions",
};

Concepts :
- window = objet global du navigateur (comme une boîte aux lettres
  accessible partout)
- APP_CONFIG = objet de configuration qu'on accroche à window
- AI_QUERY_URL = URL du service qui répond aux questions

Pourquoi un fichier séparé ?
- Pour pouvoir changer l'URL sans toucher au code métier
- En Docker, on peut remplacer localhost par le nom du service

══════════════════════════════════════════════════════════════════
5.2  utils.js — Fonctions utilitaires
══════════════════════════════════════════════════════════════════

const Utils = (() => { ... })();

Fonctions :

escapeHtml(str)
  → Convertit les caractères spéciaux HTML en entités.
  → Exemple : "<script>" devient "<script>"
  → Pourquoi ? Pour éviter les attaques XSS (injection de code).
  → Comment ? En créant un élément div, en y mettant le texte,
    et en récupérant le HTML. Le navigateur échappe automatiquement.

formatDate(isoString)
  → Convertit une date ISO (ex: "2026-07-27T12:00:00Z") en
    texte lisible en français.
  → Utilise toLocaleDateString("fr-FR", ...) qui formate selon
    les conventions françaises.
  → Try/catch : si la date est invalide, on retourne la chaîne
    originale plutôt que de planter.

translateStatus(status)
  → Traduit les statuts anglais en français :
    - "success" → "Réponse complète"
    - "partial" → "Réponse partielle"
    - "unavailable" → "Non disponible"
    - "unsupported" → "Question non prise en charge"

══════════════════════════════════════════════════════════════════
5.3  api.js — Communication avec le service
══════════════════════════════════════════════════════════════════

const Api = (() => { ... })();

Fonction principale :

async function sendQuestion(question) {
  try {
    const response = await fetch(AI_URL, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ question }),
    });
    ...
  } catch (err) {
    return { ok: false, error: "..." };
  }
}

Concepts clés :

fetch() = fonction native du navigateur pour faire des requêtes
HTTP. Elle remplace l'ancien XMLHttpRequest.

async/await = syntaxe pour gérer les opérations asynchrones
(qui prennent du temps, comme une requête réseau).
- async = la fonction retourne une promesse
- await = on attend le résultat avant de continuer

try/catch = gestion des erreurs :
- try = on essaie d'exécuter le code
- catch = si une erreur arrive, on l'attrape et on la gère

method: "POST" = on envoie des données (pas juste on en lit)
headers = métadonnées de la requête (ici : on envoie du JSON)
body = le corps de la requête, converti en JSON avec JSON.stringify

response.ok = true si le serveur a répondu avec un code 2xx
response.json() = extrait le corps JSON de la réponse

Retour :
- { ok: true, data: ... } si succès
- { ok: false, error: "..." } si échec

══════════════════════════════════════════════════════════════════
5.4  ui.js — Gestion de l'affichage (DOM)
══════════════════════════════════════════════════════════════════

const Ui = (() => { ... })();

DOM = Document Object Model = représentation de la page HTML
sous forme d'objets JavaScript. C'est comme un arbre où chaque
balise HTML est un "nœud" qu'on peut manipuler.

Fonctions :

init()
  → Récupère les références aux éléments HTML via
    document.getElementById("id")
  → Stocke ces références dans un objet elements pour y
    accéder rapidement sans re-chercher dans le DOM.

updateCharCount()
  → Lit la longueur du texte dans le textarea
  → Met à jour le compteur "0 / 1000"
  → Utilise input.value.length et input.maxLength

updateSubmitButton()
  → Active/désactive le bouton selon que le champ est vide ou non
  → submitBtn.disabled = true/false

showLoading() / hideLoading()
  → Affiche/masque l'indicateur de chargement
  → hidden = true/false
  → Désactive/réactive le textarea et le bouton

displayResponse(data)
  → Construit du HTML pour afficher la réponse
  → Utilise les classes CSS (response--success, etc.)
  → Affiche les produits et branches si présents
  → Utilise Utils.escapeHtml() pour la sécurité

displayError(message)
  → Affiche un message d'erreur dans l'alerte rouge
  → Vide la zone de réponse

Concepts DOM importants :
- element.textContent = "..."  → Change le texte (sécurisé)
- element.innerHTML = "..."    → Change le HTML (attention XSS)
- element.hidden = true/false  → Affiche/cache
- element.disabled = true/false → Active/désactive
- element.style.display = "none"/"block" → Cache/affiche

══════════════════════════════════════════════════════════════════
5.5  events.js — Gestion des événements
══════════════════════════════════════════════════════════════════

const Events = (() => { ... })();

Fonctions :

init()
  → Attache des écouteurs d'événements aux éléments HTML
  → addEventListener("événement", fonction)

Écouteurs :

input.addEventListener("input", () => { ... })
  → Se déclenche à chaque fois que l'utilisateur tape
  → Met à jour le compteur et l'état du bouton

form.addEventListener("submit", async (e) => { ... })
  → Se déclenche quand l'utilisateur envoie le formulaire
  → e.preventDefault() = empêche le rechargement de la page
  → Appelle handleSubmit()

input.addEventListener("keydown", (e) => { ... })
  → Se déclenche quand l'utilisateur appuie sur une touche
  → Si Ctrl+Enter ou Cmd+Enter, on soumet le formulaire

handleSubmit()
  → Récupère la question
  → Affiche le chargement
  → Cache les erreurs
  → Appelle Api.sendQuestion()
  → Affiche la réponse ou l'erreur

══════════════════════════════════════════════════════════════════
5.6  app.js — Point d'entrée
══════════════════════════════════════════════════════════════════

document.addEventListener("DOMContentLoaded", () => {
  Ui.init();
  Ui.updateCharCount();
  Ui.updateSubmitButton();
  Events.init();
});

DOMContentLoaded = événement qui se déclenche quand le HTML
est complètement chargé (mais pas forcément les images).

C'est le point de départ de l'application :
1. On attend que la page soit prête
2. On initialise l'UI (références DOM)
3. On met à jour l'état initial (compteur, bouton)
4. On attache les écouteurs d'événements


══════════════════════════════════════════════════════════════════════
6.  LES ICÔNES SVG
══════════════════════════════════════════════════════════════════════

SVG = Scalable Vector Graphics = format d'image vectorielle.
Contrairement aux images PNG/JPG, le SVG est du code XML qui
décrit des formes géométriques. Avantage : il peut être redimensionné
sans perte de qualité.

Structure d'un fichier SVG :

<svg xmlns="http://www.w3.org/2000/svg"
     width="24" height="24"
     viewBox="0 0 24 24"
     fill="none" stroke="#0f3460" stroke-width="2">
  <circle cx="12" cy="12" r="10" />
  <path d="M12 2 ...">
    <animateTransform ... />
  </path>
</svg>

Éléments SVG :
- <circle> = cercle (cx, cy = centre, r = rayon)
- <line> = ligne (x1,y1 à x2,y2)
- <polyline> = ligne brisée (points)
- <path> = chemin personnalisé (d = commandes de dessin)
- <animateTransform> = animation (ici : rotation)

loading.svg contient une animation : le cercle tourne grâce à
<animateTransform>. C'est le spinner de chargement.

error.svg = cercle rouge avec une croix (X)
success.svg = cercle vert avec un check (✓)

7.  COMMENT TOUT S'ASSEMBLE (FLUX D'EXÉCUTION)
══════════════════════════════════════════════════════════════════════

Étape 1 : Chargement de la page
─────────────────────────────────
1. Le navigateur lit index.html
2. Il charge style.css (qui importe reset.css, variables.css, etc.)
3. Il charge les 6 fichiers JavaScript dans l'ordre
4. L'événement DOMContentLoaded se déclenche
5. app.js initialise tout

Étape 2 : L'utilisateur tape une question
──────────────────────────────────────────
1. L'événement "input" se déclenche à chaque frappe
2. events.js appelle Ui.updateCharCount() → le compteur s'actualise
3. events.js appelle Ui.updateSubmitButton() → le bouton se débloque

Étape 3 : L'utilisateur envoie la question
───────────────────────────────────────────
1. L'événement "submit" se déclenche
2. e.preventDefault() empêche le rechargement
3. Ui.showLoading() : spinner visible, champs désactivés
4. Api.sendQuestion(question) : envoie POST /questions
5. Pendant l'attente : le spinner tourne
6. Réponse reçue :
   - Succès → Ui.displayResponse(data) : affiche la réponse colorée
   - Erreur → Ui.displayError(message) : affiche l'alerte rouge
7. Ui.hideLoading() : spinner caché, champs réactivés

9.  QUESTIONS/RÉPONSES POSSIBLES EN SOUTENANCE
══════════════════════════════════════════════════════════════════════

Q : Pourquoi avoir séparé le CSS en plusieurs fichiers ?
R : Pour la maintenabilité. Chaque fichier a un rôle précis :
    reset (normalisation), variables (configuration), layout
    (structure), components (composants). C'est plus facile à
    maintenir et à comprendre qu'un seul gros fichier.

Q : Pourquoi utiliser des variables CSS ?
R : Pour centraliser les valeurs (couleurs, espacements) et
    pouvoir les changer à un seul endroit. Ça évite les
    incohérences et les fautes de frappe.

Q : Pourquoi les scripts JS sont-ils chargés à la fin du body ?
R : Pour que le HTML soit déjà chargé quand le JS s'exécute.
    Sinon, le JS ne trouverait pas les éléments du DOM.

Q : Pourquoi utiliser async/await ?
R : Pour gérer les opérations asynchrones (requêtes réseau) de
    façon lisible, sans les "callback hell" du passé.

Q : Comment gères-tu les erreurs ?
R : Avec try/catch dans api.js. Si le serveur est inaccessible,
    on retourne un message d'erreur clair. Si la réponse HTTP
    est une erreur (4xx, 5xx), on extrait le message du JSON.

Q : Qu'est-ce que le XSS et comment t'en protèges-tu ?
R : XSS (Cross-Site Scripting) est une attaque où un utilisateur
    injecte du code malveillant. Je m'en protège en utilisant
    Utils.escapeHtml() qui convertit les caractères spéciaux
    en entités HTML.

Q : Pourquoi ne pas avoir utilisé un framework comme React ?
R : Pour une page simple avec un seul formulaire, React serait
    trop lourd. Le vanilla JS est plus léger, plus rapide à
    charger, et plus facile à comprendre pour une petite
    application.

Q : Comment fonctionne la communication avec le service ?
R : Via fetch() qui envoie une requête POST avec la question
    en JSON. Le service répond avec un JSON structuré contenant
    le statut, la réponse, et les données.

Q : Quels sont les différents statuts de réponse ?
R : success (vert), partial (jaune), unavailable (bleu),
    unsupported (rouge). Chaque statut a une classe CSS
    différente qui change la couleur de fond et du texte.

Q : Comment as-tu géré l'accessibilité ?
R : Avec aria-live="polite" pour que les lecteurs d'écran
    annoncent les changements, aria-hidden pour cacher les
    éléments décoratifs, et un label caché pour le textarea.
